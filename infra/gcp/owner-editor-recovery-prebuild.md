# Recovery pair prebuild in the existing protected workflow

The retained historical 9df pair is not accepted as a current compatible recovery pair: the retained collection documentation leaves cryptographic verification and current configuration/API/schema compatibility unqualified. A bounded inventory of the most recent twelve deploy runs contains no newer qualified normal build. This is a bounded evidence disposition, not proof that no other artifact exists.

Before closing traffic or initializing the editor, freeze and qualify final main S including the needed creation/removal and bootstrap source. After source review and explicit operational allocation, enable/dispatch only the existing `deploy.yml` workflow's `build_only: true` mode on main, with `sha: S`, `components: full`, `persistence: firestore`, qualification off, break-glass false and no bootstrap inputs. Do not dispatch a normal release hoping readiness will fail after building. No dispatch, workflow enablement or IAM action is authorized by this document.

Build-only is default false. It requires first attempt, trusted main workflow/source equality, and the existing successful exact-main CI verifier before authentication. The ordinary image matrix performs its normal build, image smoke, scan, SBOM, registry push and keyless signing/SBOM attestation. The entire release job is unconditionally skipped, including its delivery guard, native admission, restore and cleanup steps; the separate read-only qualifier is skipped too. No Cloud Run revision/traffic/config, delivery control, database or editor metadata is changed. Registry and signing writes are the intended future build operations. The existing production environment and non-cancelling production-deploy lock remain unchanged.

Retain both agent and web `release-sboms-S-IMAGE` artifacts only from a terminal successful build-only run whose complete required image matrix succeeded. Each image has an `IMAGE-build-receipt.json` with the single digest reported by Docker push, independently matched to Artifact Registry, stable local image ID, exact S, workflow/run/attempt, and SHA256 of its SBOM. Agent also retains its existing shipping-image smoke receipt bound to the same registry digest. Sign and attest the digest, never a mutable tag. Signature and SBOM Sigstore bundles are retained in the same artifact, which is uploaded only after signing/attestation completes. Bundle creation does not add registry queries or a second authentication path. A failed/cancelled matrix does not qualify a pair.

Root's recovery review must bind those two immutable digest references to source S, successful normal build/scan/smoke/signing evidence, expected main workflow signing identity and matching SBOM attestations, plus the captured service account/env/secret/template/scaling configuration. Verify the source pair's actual marker-aware web/agent contracts and native format/schema/API compatibility, and accept the concrete forward/disable procedure. A digest or signed SBOM alone does not establish compatibility, functioning service behavior, or safe live recovery. Neither an old legacy pair nor the current browse-only OOM relief can substitute after new writer admission.

Keep the qualified pair and its evidence retained through release/acceptance. Hold current-only image cleanup and any other owned deletion path; do not let a subsequent normal release delete the unserved recovery digests. Build-only itself never runs cleanup. A later normal release may rebuild S and move its tags: the recovery references remain the prebuild's exact digests, not whichever image a tag names later. There is no image-reuse deployment bypass in this change. Normal protected delivery still performs all its source, readiness, identity, signing and admission checks and may spend build time during the reviewed outage.

Only after the pair and configuration/procedure are accepted should action-time holds, actual settlement, fresh packet review/dry-run/initialization, disable contingency and protected paired release proceed. Failure after possible editor admission requires marker-aware forward/disable recovery; never restore legacy writers or delete/restore the cursor. A provider operation with an uncertain result must reconcile its original identity before another write.

The pinned installer defaults to Cosign v3.0.6; its [sign](https://github.com/sigstore/cosign/blob/v3.0.6/doc/cosign_sign.md) and [attest](https://github.com/sigstore/cosign/blob/v3.0.6/doc/cosign_attest.md) commands support local bundle output. Root can retain and verify those exact bundles with the existing trusted verifier/root material; no new broad registry collector is required.
