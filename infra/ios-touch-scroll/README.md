# Source-only touch scroll smoke

This opt-in harness mounts **AssistantApp → WindowGroup → RootView → NavigationStack → ChatView**, including the crown, root overlays, composer and native gesture ownership. It uses runtime safe areas. It does not copy the transcript or create a second window, modify scroll offsets, inject recognizers, or add CI.

The `AssistantScrollPerformance` scheme selects the optimized `ScrollPerformance` configuration. That configuration alone defines `ASSISTANT_SCROLL_FIXTURE`. The UI test must also launch with `--assistant-scroll-fixture`; a fixture binary without it fails closed. The fixture app/extension have separate bundle identifiers. The ordinary Assistant scheme file, existing Debug/Release settings and normal archive behavior are unchanged.

The compile-only app factory uses a unique empty defaults suite, fake API token, ephemeral intercepted URLSession, in-memory calendar source/record store and no-op token/speech/notification/location dependencies. Every unknown request is rejected with a diagnostic failure; no network fallback exists. The mixed 500-row Markdown/recall/card payload and bootstrap shape reuse the existing performance fixtures. This is retained-session history, not a claim that cold bootstrap normally fetches 500 rows.

Before mounting RootView, the fixture fetches the fake bootstrap through the production APIClient and installs its conversation into the production model. This deliberately bypasses normal pairing, account recovery, card-form secure storage and foreground service/polling setup. RootView's lifecycle tasks and notification subscription are excluded only in this fixture build. ChatView's speech listener does not construct an audio engine in this build. The actual UI tree, reader gestures and rendering remain in use. This quiet test does **not** validate credential/bootstrap integration, polling, streaming, notification delivery, or production service overlap.

## Handoff validation (lead owns all execution)

1. Review the diff against `a9680df1ead7331666122f31b2ce978783844109`. Confirm the normal Assistant scheme is byte-identical and only the new configuration defines the flag. Review production paths with the flag absent. Independently inspect privacy isolation and root/gesture parity.
2. On the eventual runner, run `infra/ios-touch-scroll/verify-sdk.sh iphonesimulator` (or `iphoneos`) before compiling. This reads the selected public SDK, not a toolchain version guess. Installed local headers establish `XCTHitchMetric(application:)` at iOS 26+, and `XCTOSSignpostMetric.scrollingAndDecelerationMetric` at iOS 15+. The app targets iOS 26. Primary references: [hitch metric](https://developer.apple.com/documentation/xctest/xcthitchmetric), [scrolling/deceleration metric](https://developer.apple.com/documentation/xctest/xctossignpostmetric/scrollinganddecelerationmetric).
3. Lead compiles the dedicated scheme first, reviews compiler diagnostics, then runs **only** `AssistantScrollUITests/ConversationTouchScrollTests/testOneDragAndDeceleration` on the selected destination with a retained result bundle and an external bounded timeout. No full matrix or CI dispatch yet. Keep the tested source SHA and selected SDK/device identity with the artifact.
4. The smoke relaunches outside measurement for a fresh model/anchor. It requires a settled bottom anchor and enough retained content, performs one public gutter drag toward older messages, and waits at most eight seconds for idle/settled completion. It requires actual movement, an interacting phase, a decelerating phase, stable content and a complete phase interval. No synthetic `setContentOffset` driver is involved. XCTest's one measured iteration also has one discarded warm-up; each starts from a fresh launch. Failure/timeout/missing diagnostics invalidates the run.
5. Review `touch-scroll-smoke-receipt.json` and test success. Export metrics with the selected toolchain's documented command: `xcrun xcresulttool get test-results metrics --path <result.xcresult> > <metrics.json>`. Read `--help`/`--schema` on that runner if its schema differs. Run `python3 infra/ios-touch-scroll/audit-metrics.py <metrics.json>` to inventory actual identifiers (this intentionally exits without acceptance). Identify the actual app hitch metric and **duration** metric for the combined scroll interval, then rerun with `--hitch-id <exact-id> --scroll-duration-id <exact-id>`. Review their names/units to substantiate that mapping. Missing samples, missing identifiers, empty runs and zero scrolling durations are invalid; never report them as zero hitches. Do not substitute guessed identifiers. The local tool's exported schema has `testIdentifier`, `testRuns`, `metrics`, `identifier`, `measurements`, and `unitOfMeasurement`; unknown schemas fail closed.
6. QA checks screenshot/root chrome parity, reader gesture ownership, and that the fling actually decelerates without opening the menu, selecting text, or mutating content. Simulator measurements are regression evidence only. Physical acceptance requires the same test on an identified device, refresh-rate/low-power/thermal/Reduced Motion settings recorded, metric artifacts and visual interaction review. This smoke establishes neither sustained 60 fps nor overall production readiness.

Diagnostics store small non-observable geometry/phase values. Accessibility encodes a receipt only when queried; there is no per-frame UI publication or per-frame JSON. The settling wait and accessibility polling remain part of this bounded diagnostic workload, so compare only like-for-like runs. There is no performance threshold or baseline in this source packet.

No build, test, app/device launch, push, or CI run was performed during source implementation.
