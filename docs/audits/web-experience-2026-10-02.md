# Web experience review — October 2, 2026

The browser currently serves as the owner's mobile-access and investigation console. Six page routes are reachable; `/` redirects to Settings, and 27 retained product routes redirect to Settings before their page components run. This is an intentional rule in [the proxy](../../apps/web/proxy.ts), independent of PostgreSQL versus Firestore. The source inventory is therefore larger than the current browser product. Re-enabling those routes is a product decision, not a styling repair.

This review inspected all 34 `page.tsx` files, their principal presentation components, the root layout, shared primitives, error/loading boundaries, and route policy. The six reachable pages were rendered with synthetic data and actual application components/CSS. Dormant pages were reviewed in source; their appearance and live performance were **not** browser-verified. Production records, provider credentials, model calls, and production configuration were not used.

## Changes delivered

- The owner console has active navigation, a discoverable Security destination in passkey mode, a first keyboard stop that skips chrome, and preserved pinch zoom. At 320px its two-row header is 117px tall; appearance is accessible from a labelled 44px menu trigger rather than taking a third navigation row.
- Appearance supports System, Light, and Dark in the header popover. System appearance follows OS changes; saved appearance synchronizes between tabs. Blocked browser storage still allows the current tab to change appearance. The root-error fallback uses the same pre-paint theme bootstrap.
- Settings focuses on connecting devices. Full passkey, recovery, and session management belongs to Security. Pairing loads only device keys, reducing its initial owner-API requests from two to one.
- Security distinguishes loading, an empty account, a failed read, and a successful read. Initial requests abort on navigation. A failed initial load has a retry action. Compact date labels preserve full timestamps in their `time` attributes and titles. Per-device/passkey actions live in labelled overflow menus; revocation, passkey removal, recovery-code replacement, and signing out everywhere use the existing explicit confirmation behavior. The last passkey remains protected by the existing guard.
- Shared-token pairing explains that a masked preview cannot connect a device, gives a usable full-key next step, and places server configuration behind a disclosure. Replacement-key effects are explained before confirmation; the resulting full key remains selectable and copyable.
- Audit filters use readable labels and consistent controls. The list shows result counts, a way to clear filters, meaningful empty states, a warning at its 100-record boundary, and explicitly labelled UTC timestamps. Links to individual diagnostic records do not prefetch automatically.
- Audit investigations put selected evidence before assistant investigation and diagnostic disclosures. The first evidence heading is at 607px in the 320px synthetic case, within the initial 740px viewport. They use the shared status vocabulary, monetary formatting, visible disclosure affordances, selected section styling, and readable request fields. On phones, a section selector replaces nine wrapping navigation buttons. Evidence-section/continuation links do not trigger speculative reads.
- Root navigation goes directly to Settings, avoiding the old `/` → `/chat` → `/settings` path. The missing-page escape goes to Settings. Error recovery uses the installed Next.js `retry` API, and a root error boundary covers layout/authentication failure.
- KaTeX styling is imported by the retained math renderer instead of every browser page. Console pages no longer need the math stylesheet and its font declarations.
- Recovery, newly issued device/shared keys, and investigation requests share a copy control with readable success/error feedback and a manual fallback. Newly issued codes receive keyboard focus. Recovery acknowledgement uses a real disabled button, resets for a replacement code, and fits a 320px phone. Closing recovery clears its sensitive input. Failed shared-key replacement keeps the previously issued one-time key available.
- Overflow actions use the browser's native popover invoker relationship, preserve keyboard order, return focus on Escape, and clamp placement within a short viewport. Passkey errors distinguish cancellation, an already registered device, unsupported passkeys, and opening the wrong server address.

No browser product routes were re-enabled and no API authentication/persistence policy was changed.

## Design direction and implementation constraints

The assistant should feel calm, prepared, and attentive. The main conversation earns the strongest identity; supporting pages should help the owner make a decision or understand a fact with less effort. A trustworthy assistant names what happened, what remains uncertain, and what comes next. An empty state should make a concrete next action possible, and an unavailable read should never masquerade as empty data.

The existing green-paper identity is retained. Light tokens are canvas `#eef5f0`, raised `#ffffff`, sunken `#e3ede6`, edge `#d3e1d7`, strong text `#15201a`, muted text `#5a6d62`, and accent `#217a4b`. Dark equivalents are `#121a15`, `#19241d`, `#243129`, `#38473d`, `#eef5ef`, `#9cb0a2`, and `#6fcb9c`. Dark accent-filled controls use `#0d1f16` text. These semantic names are implemented in [globals.css](../../apps/web/app/globals.css), and should stay the shared vocabulary.

Use the platform system typeface for page titles, prose, labels, and controls; monospace belongs to IDs, code, and diagnostic keys. The existing 12/14/16/18/24/30px scale, 16px cards, 8px controls, restrained tonal depth, and 44px phone targets form a reasonable foundation. Regular labels should use sentence case. The old uppercase-monospaced `microLabelClass` spans dormant product surfaces and should be narrowed during their next deliberate design pass.

Responsive hierarchy is information architecture: on a phone, nine evidence buttons should become a single labelled selector; a header must wrap without clipping; long addresses and IDs must remain readable. Focus-visible outlines, native select/disclosure/dialog behavior, a keyboard skip link, browser zoom, meaningful status text, and Reduce Motion are part of the normal design contract. Global view-timeline card reveals deserve reconsideration: they add movement to routine scanning and can create containing-block surprises for overlays. The reachable console adds no new entrance choreography.

See the shared [design system](../design-system.md) for the cross-client guidelines. The browser owner console and native product should share semantic behavior while retaining their own appropriate navigation and input interaction.

## Architecture and performance findings

1. **Treat route policy as an explicit product contract.** The current repository contains a retired browser product and a live owner console. Source-only page tests can pass for pages unreachable in production. Maintain a tested route inventory and label dormant functionality in documentation. Do not spend UI effort on unavailable surfaces while presenting it as a delivered browser feature.
2. **Finish the projection boundary before broad UI expansion.** Many retained pages construct Firestore repositories and PostgreSQL branches themselves. UI should request an owner-scoped typed projection from the application, with shared limits, privacy fences, and capabilities. Storage technology should not select the product menu.
3. **Bound reads and client work independently.** Paging task timelines and audit fields is a strong pattern. People/catalog search should happen in the repository at scale. A collapsed disclosure still contributes its server-rendered payload; hiding content does not avoid fetching or serializing it.
4. **Measure real user-visible service latency separately from synthetic rendering.** The local harness proves component layout and client behavior with instant mocked owner APIs. It cannot establish auth, Firestore/PostgreSQL, Cloud Run cold-start, third-party, or large-account latency. Before claiming a performance improvement end to end, profile Settings device-read p95, audit first-byte/content-ready p95, audit overview query counts, transferred RSC bytes, and a populated long conversation's frame/interaction behavior.
5. **Use conditional or event-driven updates.** Existing AutoRefresh backs off to two minutes and pauses while hidden. It still scans main text and reruns RSC queries to detect change. A cheap version/ETag or event projection would avoid full data reads when nothing changed; active-call and active-work refresh budgets should be distinct. The reachable read-only audit console deliberately does not add continuous polling.
6. **Keep expensive dependencies local to the surface that uses them.** KaTeX now stays with the math renderer. Mermaid already uses a dynamic import. Broad markdown/parsing libraries should not become owner-console requirements. Existing root `force-dynamic` is appropriate for private owner state but requires measuring request waterfalls rather than adding indiscriminate caching.
7. **Create one attention model across clients.** Activity, approvals, goals, memories, anomalies, and calls are views over work and decisions. The assistant should prioritize an actionable interruption once, show the same resolution everywhere, and preserve a quiet status when there is nothing to do. Repeated prompts are a state/projection defect rather than a reason to add another badge.

Notification payloads express navigation intent; they do not authorize access. The decoder accepts known routes, rejects malformed owner fields, and treats path/URL/malformed conversation values as absent. The coordinator waits for authenticated startup, ignores an explicitly different owner, and verifies that the owner-scoped server response matches the requested conversation. Missing, foreign, or mismatched destinations show the authenticated main thread with an explanation. Conversation navigation waits for an active turn's local settlement. Each concurrent turn cleanup owns its own settlement token, so an older cancellation cannot release a newer cleanup's navigation guard. A later notice, explicit chat selection, manual page/person/back navigation, or changed connection invalidates an older in-flight notice request, preventing delayed responses from replacing newer navigation.

That precedence applies in both directions: a slow manual conversation read also checks the navigation version, owner, client configuration, and cancellation before applying its result or reporting an error. Opening a conversation cancels its predecessor's held idle poll and starts a fresh foreground loop. Each idle result checks cancellation, foreground/turn state, polling generation, owner, configuration, conversation, and the original cursor before changing rows or cursor. An old response therefore cannot contaminate the new chat, even when cancellation loses a race or the owner switches away and back to the same thread. Local idle-reply notifications use captured owner/conversation/title values, so an asynchronous notification-settings lookup cannot relabel a side-chat notice with a subsequently selected chat.

These changes preserve application hydration and existing inline suggestion decisions. They do not modify proactive selection, persistence, schemas, or approval admission. Approval notices keep the existing Approvals destination and now carry owner identity; the server notifier does not have an approval ID and does not invent one.

Verification is deliberately bounded:

- Thirteen focused server/web tests pass across push payloads, retained receipt routing, suggestion state, and preserved suggestion context. Modules and web typechecks, formatting checks, and `git diff --check` pass.
- Eleven new native routing/continuity tests cover malformed identifiers, deferred startup, legacy main-thread fallback, foreign-owner rejection, missing/mismatched conversations, newer-notice precedence, explicit chat/page/back navigation precedence in both request orders, overlapping cleanup tokens, and stale idle rows/cursor after a thread change. A generic iOS Simulator `build-for-testing` succeeds, compiling those tests alongside the application. This machine has no installed runnable simulator runtime, so these XCTest cases were not executed.
- A separate Foundation host harness executed thirty-one checks using the actual extracted destination/coordinator, manual navigation, idle-read/poll-lifecycle methods, and settlement state with small UI/network stubs. Cases include active-turn deferral, manual page/back navigation, overlapping cleanup release, idle-loop cancellation/restart, stale responses after owner/configuration/cursor/cancellation/send changes, switching away and back to the original thread, and captured local-notice metadata. This validates routing policy and race handling independently of UIKit; it is not a complete iOS app, APNs delivery, or lock-screen interaction test.
- The existing 72-case console screenshot matrix remains evidence for the visual changes above. This source-level continuity follow-up does not claim an additional rendered chat or native notification screenshot.

Physical notification taps, cold launch from the lock screen, real APNs delivery, and voice/turn continuation still need an installed-device acceptance pass before a release claim.

## Owner-console refinement, 3 October 2026

A further source and browser pass focused on actual owner actions rather than adding more surfaces. It found small failures that made the otherwise calm console feel uncertain: recovery codes could overflow the smallest phone; recovery opened without moving keyboard focus and had no way to clear the entered code by closing it; copy failures were silent or replaced a compact button with a long instruction; failed key replacement removed the previous receipt; newly issued codes appeared above the focused control; and overflow menus lacked the native invoker relationship that supplies keyboard order and focus restoration.

The new shared [copy control](../../apps/web/lib/copy-button.tsx) keeps feedback beside the readable value and provides a manual fallback when the clipboard is denied. Feedback belongs to the exact value being copied, so replacing a code resets it and a late old operation cannot claim the replacement was copied. [Recovery](../../apps/web/app/setup/recovery-code.tsx) uses grouped, selectable code text that fits 320px, focuses its heading, exposes a 44px acknowledgement target, and enables a real Continue button only after acknowledgement. A replacement code resets that acknowledgement. [Sign-in recovery](../../apps/web/app/signin/signin-client.tsx) uses a native disclosure with input focus on opening, sensitive-value clearing on closing, and a single typed pending state.
