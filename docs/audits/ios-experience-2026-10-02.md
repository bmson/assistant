Reviewed on 2026-10-02, with implementation and validation follow-ups on 2026-10-03. This review covers the reachable iPhone destinations, their supporting sheets and editors, speech, transport, and system surfaces. It evaluates the current source and makes targeted improvements. ## Product direction

The native product should feel like an attentive person who has a good filing system. Conversation is the main place to work. Other destinations let the owner see what the assistant is doing, correct its understanding, and decide what it may do. The assistant should know when to speak, when to wait, and when a detail belongs behind a disclosure rather than in a long message.

The existing green conversation stage and paper-like replies provide a distinct identity. Preserve them. Utility screens should use calmer canvas surfaces and native navigation; they should not compete with the conversation. The most valuable improvement is coherent behavior: a decision is visibly waiting, a failed read is recoverable, an old snapshot is identified, an accepted action has an honest receipt, and microphone activity is deliberate.

A companion face can support listening, but expression must not substitute for evidence. A human-like voice still needs short answers, interruptibility, clear microphone state, and an explicit transition from a spoken request to an approval on screen.

## Changes implemented in this review

1. **The conversation has an independent rendering boundary.** `ChatTranscriptRows` owns receipt grouping, prompt lookup, the eager stack, row construction, and message insertion animation. Its equatable inputs are messages and send availability. Typing, composer measurements, and pull-menu motion no longer offer the full row-building work on each change. Existing row equality and Markdown memoization remain. The eager viewport and native composer geometry are preserved; no virtualization or gesture replacement was introduced.
2. **Hands-free implements its documented decision boundary.** `TalkView` now has a `needsDecision` phase. A pending approval or budget gate stops listening, announces that review is needed, and provides a visible review route. Suggestions are not approval gates. A decision settled elsewhere offers an explicit Resume action. Leaving the foreground ends Talk mode and speech; returning does not reopen the microphone automatically. A completed turn with no queued speech returns to listening instead of waiting for a speech event that never occurs.
3. **Hands-free is discoverable.** More → Speech contains “Talk to the assistant,” alongside the existing microphone accessibility action. It cannot start over a turn already sending. Existing tap/hold dictation remains a draft that requires Send.
4. **Calls have a recoverable loading state.** A failure no longer leaves a permanent spinner or erases a previously loaded call list. Call detail follows a live call only while the scene is active. Cancellation exits the wait before another request. Repeated failures back off and stop after three failures with an explicit retry. Sending an answer and hanging up share a mutation guard; blank newline-only answers cannot be submitted.
5. **The memory library distinguishes failure from emptiness.** Failed queries expose recovery and identify previous results. Actions/paging are disabled while results are stale or loading. Row action labels refer to the query that actually produced the displayed rows. Clearing the native search control clears the applied search. Tracked requests cancel when the screen leaves, and an unfinished filter resumes on return. Per-row mutation guards prevent duplicate actions without confusing two simultaneous rows.
6. **Connection guidance speaks to the owner.** Pairing points to web Settings → Mobile app and asks for a pasted access key. A candidate connection must authenticate before replacing the current owner, credentials or caches; failure preserves the current session. Environment variable names and server shell commands move out of the app flow; operator details remain in the repository documentation.
7. **Failure presentation is reusable.** `AssistantLoadFailureState` provides the same semantic typography, panel, recovery action, and accessibility grouping for failed reads.
8. **Secondary ink matches the shared design system.** Light `inkMuted` is `#5A6D62`, improving calculated contrast against opaque sunken `#E3EDE6` from 4.30:1 to 4.61:1. Callers use semantic secondary text, glyphs, charts and decorative strokes; none requires a separate native shade. Dark ink, geometry and behavior are unchanged. This is a color-pair calculation, not a rendered accessibility certification.
9. **Graph preparation leaves the UI thread.** The initial 150 force passes, the preview's bounded 400 passes, and Reduce Motion replacements prepare a value copy in cancellable background work. Snapshot/force generations reject obsolete results; touch and navigation take priority, and removal releases work. Normal motion adopts the prepared positions through the existing interpolation; Reduce Motion publishes a still replacement after navigation releases. Current display settings and a touched viewport remain authoritative. Live frame physics remains pairwise and requires device profiling. See [graph performance](../../apps/ios/docs/graph-performance.md).
10. **Notification navigation retains conversation identity.** Remote and local chat notices identify their owner and destination; authenticated lookup restores that conversation, with legacy main-thread fallback. Cold launch and active turn cleanup defer navigation; per-cleanup tokens, navigation versions and held-poll guards prevent old work replacing a newer selection or contaminating its messages/cursor. See the [continuity validation](web-experience-2026-10-02.md#continuity-follow-up-3-october-2026).
11. **Utilities distinguish a failed read from an empty account.** More, Reminders, AI providers, Connected tools and Workspace use authenticated refresh outcomes, named loading states and the shared recovery panel. Retained settings remain visible but mutations wait for recovery. Workspace actions serialize, preventing one issue or improvement from overlapping another. The Documents initial read can now fail visibly; an old Documents overview still needs its own freshness outcome when only the workspace refresh succeeds.
12. **Setup and editing have clearer ownership.** More has one personal-preferences row, then personal interaction settings and a Services group. Connected tools lists existing connections before a disclosed setup form, and describes the real approval/autonomy policy. More refreshes settings without reopening the main transcript or prefetching MCP. Provider setup retains a pasted key on a failed save, clears it only after the server saves the connection, and distinguishes a saved connection with a failed test. Model defaults preserve each unsaved local choice while untouched fields follow server changes. Phone-call voice and iPhone read-aloud settings are explicitly distinct.
13. **Recovery stays inside the form.** Personal preferences, skill, cost and writing-voice editors retain draft fields and display submission failures in the presented editor. Save and dismissal guards prevent ambiguous duplicate submissions. Writing voice cannot be edited or saved until its initial read succeeds; an unavailable profile offers Retry rather than an editable blank profile. Memory export and erasure cannot overlap, and erasure success reflects the actual server receipt. Chat creation, directory selection and per-chat model changes explain that the current reply must finish or stop first.
14. **Every finished output has a readable state.** Empty/tool-only assistant rows and cards unsupported by this client now explain that no readable answer is available and offer Activity review. The fallback runs only after streaming settles and only when prose, native cards, decisions, notices and suggestions cannot supply content. It exposes no raw tool payload and infers no completed action. Recognized notices render even without prose. Interrupted-response copy no longer assumes that nothing changed, and its Retry control reaches 44pt. Approved receipts describe permission; rejected, failed, expired, cancelled and unknown decisions have distinct recovery. Inline approval/standing-permission failures remain visible beside the controls and announce an unconfirmed result.
15. **Self-improvement receipts describe actual outcomes.** Native proposals use the server’s additive outcome/enacted/detail response, distinguishing a routing change, advisory acknowledgment, already-current configuration and an already-decided proposal. A single supported request_fix action replaces the duplicate unsupported request_code_fix control. A code-fix receipt links the existing report and its actual status; it does not invent another coding run. Local acknowledgments prevent repeat actions until fresh projections arrive and clear with the authenticated session. Code fixes now retain past reports, merged revision and history, show typed milestone guidance, provide allowance-limited retry separately from confirmed manual attempts, and require owner confirmation after detected deployment.

The implementation adds no third-party native dependency, changes no provider credential, deploys nothing, and preserves native UIKit text selection, safe-area ownership, and Reduce Motion behavior.

## Native architecture decisions to keep

- The phone is a presentation and capture client. Durable workflows, tools, credentials, schedules and long-term memory stay on the owner's server. A suspended app does not cancel the assistant's work.
- `/api/mobile/v1` exposes application projections. Personal dates and relationships are worded centrally; the phone does not independently infer memories or relationship truth.
- `APIClient` has a testable session seam; `Transport` owns and resets stale pooled connections after suspension. Cancellation is not presented as an actionable server failure.
- Approval/suggestion decisions are tracked locally until authoritative reconciliation, so old reads cannot undo a successful decision. Preserve this when splitting the state owner.
- UIKit owns caret movement and text selection. SwiftUI menu recognition observes deliberate vertical intent and never replaces native selection gestures.
- The conversation surface owns pull motion and its safe-area allowance once. Transcript and composer remain siblings. A menu optimization cannot change this physical relationship casually.
- Rendering is a pure projection of grounded message parts. Memoization is bounded; unknown metadata must not become invented facts. Spoken output is a separate projection of the same content contract.
- Native Forms and Lists handle settings, editing and ordinary directories. Custom graphics earn their place only for the conversation and relationship map.

## Architecture that still needs improvement

`AppModel` is a large state owner combining transport orchestration, canonical conversation merge, decision reconciliation, workspace mutations, memory/person reads, speech, navigation, notifications, location and system activity. This increases invalidation breadth and makes lifecycle correctness harder to audit. Splitting it into unrelated per-screen clients would lose valuable shared invariants; extract by state ownership instead.

Recommended sequence:

1. **Conversation store:** owns message IDs/order/cursor/streamed-durable replacement, hidden-log undo and active-turn state. All message producers merge here. Expose immutable transcript snapshots, not a mutable array every screen can change.
2. **Decision store:** owns approval/suggestion transitions, optimistic pending guards, accepted-decision protection and reconciliation. Notify conversation and system activity through typed state changes. The approval inbox and inline chat must stay consistent.
3. **Workspace repository:** provides scoped cached projections (people, memory overview, settings, costs, documents), account/server generation, single-flight reads and explicit loading/failure/stale states. Avoid refetching the entire workspace after every tiny mutation. Preserve last successful results; never let an older or cancelled snapshot overwrite a newer mutation.
4. **Speech session:** owns a tested state machine for idle/preparing/listening/thinking/speaking/needs-decision/interrupted. It coordinates the listener/player and derives UI phase; view callbacks should not be the only proof that a microphone stopped. Add a clock/audio-player seam for silence, interruption and permission tests.
5. **Presentation coordinator and system adapters:** routes/deep links, notifications, badge, Live Activity and location adapter should consume store state without creating another authority for task/decision state.

Start by extracting a slice with regression tests, not migrating all 2,000+ lines at once. The transcript boundary in this review is a small example: it preserves ownership rules while reducing incidental work. The follow-up scopes composer drafts and failed-send recovery by owner/server/conversation, and fences connection-bound continuations before they can publish into a replacement session.

Screen fetches should all adopt the same contract: `not loaded`, `loading(previous)`, `loaded(snapshot, freshness)`, `failed(previous, retry)`. The utility follow-up implements explicit outcomes for providers, MCP, writing-voice editing and workspace/settings consumers. Cards, profile summary and cached Documents overview still need the same contract. A shared repository would prevent each view recreating these transitions.
