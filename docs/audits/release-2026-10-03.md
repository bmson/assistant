## Integration changes

- Preserve the incoming bounded Firestore reads, in-flight read sharing and native per-property Observation model.
- Keep draft scope and recovery observable; preserve navigation, notification, request cancellation and owner-replacement guards. Parallel bootstrap/overview requests are retained for the same owner; an overview observed before an owner replacement is discarded and read again for the new owner.
- Use path-keyed native transport fixtures for parallel reads. Cancellation assertions permit a child request cancelled before it starts while prohibiting duplicate endpoint requests or retries.
- Prevent the PostgreSQL Notifications fallback lock cycle with an owner `FOR NO KEY UPDATE` lock. Admissions remain serialized and privacy erasure remains fenced. A real concurrent creation test verifies one destination and linked message, suggestion and admission ledger. No schema migration is introduced.
- Update the built-console smoke checks to the reviewed Settings and Audit wording. Give the measured database-backed scenario replays their documented 30-second deadline without weakening any assertions.
- Keep the screenshot gallery in Git and exclude its large evidence assets from Docker/Cloud Build inputs. Production images do not copy those documents.

## Release proof and delivery boundary

The GitHub pipeline releases the clean committed source after CI succeeds. At this release preparation, its repository variable `PERSISTENCE_DRIVER` is `firestore`; the release script independently checks both live service templates and refuses a driver mismatch. Local operator credentials could not read those templates, so this record does not infer live persistence from the health endpoint alone. Production deployment must preserve the live persistence driver, pass recovery/index gates, and report the exact release commit through public `/api/health`. Terminal CI, iOS and deployment workflow results and an independent health read are required before calling this deployed. Native CI builds/tests a simulator app; it does not sign or distribute an iPhone update.

Existing in-flight overview/workspace sharing can return a pre-write projection to a read begun after a mutation. Credential routes do not use that sharing; confirmed approval and improvement receipts retain their local reconciliation guards. A general mutation freshness fence remains separate follow-up work; this release does not claim to implement one.
